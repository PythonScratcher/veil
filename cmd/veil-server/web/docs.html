Veil REST API

The base URL is the admin panel address followed by api/v1, for example https://your-server:8088/console-…/api/v1. Create API keys in the panel under API. Send the key on every request:

Authorization: Bearer veil_xxxxxxxx_…     (or: X-API-Key: veil_xxxxxxxx_…)

Requests and responses are JSON. Errors look like {"error": "message"} with a 4xx status. Read only keys may only use GET. Full access keys may use everything below. API keys cannot create or revoke API keys; that is only possible in the panel. Ten failed authentications from one address block it for 10 minutes. If the panel uses Veil's self-signed certificate, pin it in your client or use curl -k.

Server

GET/meThe API key in use: id, name, scope, expiry.
GET/serverMain domain, port, uptime, number of keys, open tunnels, total traffic and current speed.
GET/statsSame as /server.
GET/history?range=24hTraffic over time for all keys. Ranges: 1h, 6h, 24h, 7d, 30d. Returns step, points and per_key shares.

Users (client keys)

GET/usersAll keys. Filters: ?status=active|disabled|expired|capped, ?q=text (name or note).
POST/usersCreate a key. Body: a user object; name is required. Returns the key (201).
POST/users/bulkCreate many keys with the same limits: {"count": 20, "name_prefix": "class-", "user": {…}, "domain": "vpn.example.com"}. Returns each key with its client config.
GET/users/{id}One key, with live status, open connections, client IPs and current speed.
PATCH/users/{id}Change any fields of the user object. POST /users/{id}/update does the same for clients that cannot send PATCH.
DELETE/users/{id}Delete the key and cut its tunnels.
POST/users/{id}/enableEnable the key.
POST/users/{id}/disableDisable the key and cut its tunnels.
POST/users/{id}/kickDisconnect its open tunnels now (the client may reconnect).
POST/users/{id}/reset-usageSet the data used counter back to zero.
POST/users/{id}/regen-keyGive the key a new secret. The old client config stops working at once.
GET/users/{id}/config?domain=The client config (client.json) to import in the Veil apps. Optional domain picks which of the server's domains goes in it.
GET/users/{id}/qr.png?domain=The same config as a QR code (PNG) for the Android app.
GET/users/{id}/history?range=7dTraffic over time for one key.

User object (input)

Every field is optional on PATCH; only the fields you send change.

namestringUp to 64 characters.
notestringFree text.
enabledbool
expires_atunix seconds0 = never expires.
add_daysnumberExtend the expiry (from now if already expired).
data_cap_bytesintegerTotal up + down allowed. 0 = unlimited.
add_data_bytesintegerTop up the data cap.
rate_mbpsnumberSpeed cap per direction. 0 = unlimited.
max_devicesintegerSimultaneous client addresses. 0 = unlimited.
reset_daysintegerReset the data counter every N days. 0 = never.

Responses also include id, status, used_up, used_down, conns, ips, speed_up, speed_down, last_seen and created.

Domains

GET/domainsThe main domain (from server.json) and every extra domain, with certificate type, whether it is the default for new configs, and what its DNS resolves to.
POST/domainsAdd a domain: {"name": "vpn2.example.com", "cert": "letsencrypt" | "server", "note": "…"}. Let's Encrypt certificates are requested right away and renew themselves.
GET/domains/{name}?check=1One domain. With check=1, also fetches (or issues) its certificate and reports issuer, expiry and errors.
PATCH/domains/{name}Change cert or note.
POST/domains/{name}/primaryMake it the default domain in new client configs. Use the main domain's name to go back to it.
DELETE/domains/{name}Remove an extra domain.

Examples

API=https://your-server:8088/console-…/api/v1
KEY=veil_xxxxxxxx_…

# new key: 30 days, 50 GB, 20 Mbps
curl -k -H "Authorization: Bearer $KEY" -X POST $API/users \
  -d '{"name":"alice","add_days":30,"data_cap_bytes":50000000000,"rate_mbps":20}'

# add 10 GB to a key
curl -k -H "Authorization: Bearer $KEY" -X PATCH $API/users/ID -d '{"add_data_bytes":10000000000}'

# client config for a specific domain
curl -k -H "Authorization: Bearer $KEY" "$API/users/ID/config?domain=vpn2.example.com"

# keys that ran out of data
curl -k -H "Authorization: Bearer $KEY" "$API/users?status=capped"
